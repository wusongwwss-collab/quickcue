# 会中辅助（quickcue）· 宿主无关用法说明书

> 本文件写给「任何支持 MCP 的宿主 / 代理」看：无论你运行在哪种宿主环境里，
> 按本说明即可接入 quickcue 的会议侧规则包并正确使用其工具面。

## 是什么

quickcue（中文显示名「会中辅助」）是**本地规则判定引擎 + 会议辅助规则包**：

- **会中辅助**（会议辅助包）：对对话文本流做疑问判定与强度打分，命中规则的
  客户疑问句变成一张「一句话提示卡」（话术参考 + 证据行），10 秒未处理自动
  过期，出卡频率由冷却闸克制。

特性：零第三方依赖、零模型调用、零联网、零账号——闸参数与判据词表全部以
本地 YAML 描述（当前版本引擎内置默认值与示例文件逐字一致，规则文件自动
加载属后续版本能力）；改动自动记成 delta（差异，仅结构与参数），可分享。

## 工具面

| 工具 | 作用 |
| --- | --- |
| `cue.analyze` | 输入对话文本流（含发言角色标注更佳），对命中规则的疑问句返回提示卡（话术参考 + 证据 + 有效期） |
| `rules.validate` | 校验规则包 YAML 是否合法，逐字段标出错误，建议每次改规则后先跑它 |
| `feedback.record` | 记录对某张卡的三态评价（对 / 不对 / 已处理）；评价先记本地，是否上行取决于反馈开关（默认关） |

## 在支持 MCP 的宿主中配置

服务器是 **stdio 形态**：宿主负责拉起进程、通过标准输入输出通信、
退出时回收。命令行形态：

```bash
# 会中辅助（Python 3.10+，无需安装任何依赖）
python <quickcue 仓库路径>/hosts/mcp/meeting_server.py
```

宿主配置段示例（JSON，路径替换为你本机的仓库路径）：

```json
{
  "mcpServers": {
    "quickcue-meeting": {
      "command": "python",
      "args": ["/你的路径/quickcue/hosts/mcp/meeting_server.py"]
    }
  }
}
```

配置保存后**重启宿主**，在工具列表里确认 `cue.analyze` / `rules.validate` /
`feedback.record` 可见——以宿主工具列表真实出现为准，配置文件保存成功不等于接入成功。

## 规则包放哪

- 会中辅助规则：仓库内 `packs/meeting/rules.example.yaml`（闸参数 / 判据词表 /
  话术模板全量示例，带中文注释；当前发行版引擎内置默认值与它逐字一致）；
- 运行期派生物（本地评价流水、delta 记录）在 `.quickcue/` 目录（反馈落
  `.quickcue/feedback.jsonl`，位置可用环境变量 `QUICKCUE_FEEDBACK_DIR` 覆盖）
  ——**删除这个目录即可完全卸载**，本软件不写系统目录、不留注册表项。

改规则流程：把 `rules.example.yaml` 复制为 `rules.yaml` 修改成自己的口径 →
用 `rules.validate` 校验结构 → 规则文件自动加载接入引擎后本地生效
（当前发行版行为详见 `packs/meeting/README.md`）。

## 反馈开关在哪

- **默认关闭**；首次成功出卡后会询问一次「是否开启匿名分享」，之后不再问。
- 之后可在宿主对话中直接说「打开 / 关闭匿名反馈」，或通过反馈设置页切换三档
  （仅评价 / 评价 + 规则改动结构 / 再加脱敏失败样例）。
- 反馈记录先落本地 `.quickcue/feedback.jsonl`（位置可用环境变量
  `QUICKCUE_FEEDBACK_DIR` 覆盖），默认无上行、数据只留在本机。
- 「上行记录」随时可查，能看到到底上传了什么；任何档位都不含对话原文、
  人名、公司、金额——脱敏在上传前于本机完成。

## 常见问题

1. **需要联网或 API key 吗？** 不需要。判定全在本地完成，规则、示例、话术
   都在仓内；断网环境可跑通全部演示。
2. **演示需要麦克风或录音吗？** 不需要。直接喂文本流（见 `examples/` 下的
   示例对话）即可出卡，演示全程不触碰语音链路。
3. **改了 rules.yaml 没生效？** 当前发行版引擎尚未接入规则文件自动加载，
   引擎按内置默认参数运行（与 `rules.example.yaml` 逐字一致）；规则加载属
   后续版本能力，演进状态以 `packs/meeting/README.md` 为准。规则结构问题
   仍可先用 `rules.validate` 校验。
4. **提示卡太多 / 太少？** 调闸参数：`global_cooldown_sec`（两卡最小间隔）、
   `max_per_meeting`（单场上限）、`l1_min_strength`（疑问强度阈值，调大更
   克制）；当前版本内置默认值为 60 秒 / 180 秒同型冷却 / 12 张。
5. **我的对话内容会被上传吗？** 默认完全不上传；即使主动开启匿名反馈，
   上行的也只有脱敏后的结构与评价，原文、人名、公司、金额永不出本机；
   删除 `.quickcue/` 目录即可清除全部本地派生数据。
6. **没有注入知识库也能出卡吗？** 能。`cue.analyze` 未传 `kb`、且未配置外部
   知识库（环境变量 `QUICKCUE_KB_FILE`，指向 JSON 文件）时，回退到仓内内置
   演示知识库（常见客户疑问→话术），保证零配置喂一句客户疑问就出第一张演示卡。
   **内置演示知识库仅用于开箱演示，生产用宿主注入自有知识库**（外部注入优先
   于演示库）；未命中任何话术主题的疑问句仍按原语义 `kb_miss` 静默跳过。
